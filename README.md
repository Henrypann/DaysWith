# DaysWith

**Keep the days we share.**

**留住一起度过的日子。**

DaysWith 是一个正在开发的开源家庭成长记录 App，用照片、视频和文字，留下孩子成长中的日常，让爸爸妈妈能够一起记录、一起回看。

## 为什么做 DaysWith

我最核心的需求，是记录娃的成长。

照片和视频留在各自的手机里，两个人使用的手机品牌、云服务不一样，共享相册并不总是顺手。我也不想为了两个人共享照片持续订阅，更不希望换一个手机品牌，就要重新安排家庭照片和成长记录。

因此，我想做一个围绕家庭记录的 App：把零散的照片、视频和文字整理成连续的成长时间线，再连接自己配置的腾讯云对象存储（Cloud Object Storage，COS），让记录和存储的选择有更多主动权。

减少对单一手机品牌的依赖是这个项目的目标。跨品牌双机使用、完整换机恢复仍需要进一步验证，当前版本没有无缝迁移的承诺。

## 适合谁

- 希望长期记录孩子成长，并让爸爸妈妈共同回顾的家庭。
- 愿意自行构建 App、配置和维护 COS，接受当前开发与验收状态的使用者。
- 希望参与家庭记录、媒体备份和跨设备兼容建设的开发者。

家庭成长记录是当前核心。情侣等两个人的生活记录是延伸方向；现有身份仍固定为「爸爸／妈妈」，通用成员、邀请和情侣署名尚未实现。

## 当前代码已实现什么

以下能力已在代码中实现，平台验收状态见下一节。

| 能力 | 当前范围 |
| --- | --- |
| 成长记录 | 照片、视频导入，文字记录与草稿 |
| 时间线与回顾 | 按年月浏览已有记录，回到当时的日常 |
| 父母署名与云端读取 | 固定爸爸／妈妈身份；连接同一家庭 COS 后，可刷新读取另一身份的记录 |
| 纪念日 | 自定义重要日期；年度预置为儿童节、国庆节、元旦，不预填私人生日 |
| 本地保存与回收站 | 本地档案、实现范围内的删除恢复和有效档案副本恢复 |
| COS 备份 | 用户自有存储连接、前台备份队列、状态查看与失败重试 |

本机自己的记录可编辑；其他身份或其他设备的云端记录通常只读。云端读取与备份成功，不代表新设备已经完整继承档案并能继续编辑。

后续优先完善跨品牌双机验收与换机恢复验证、可靠后台传输，再扩展自定义成员和署名。当前仅适配 COS，尚无其他存储服务适配或端到端加密。

## 开始使用与开发

先阅读 [完整 onboarding](docs/ONBOARDING.md)，其中包括工具链、首次运行、COS 配置、权限、测试模式和升级说明。

当前 Flutter 工程要求支持 Dart `^3.13.7` 的 SDK；原生 Android 需要 JDK 17、Android SDK 37 / Build Tools 36.0.0。Flutter iOS 构建需要 macOS、Xcode、CocoaPods 和 iOS 16+。具体以工程配置和 onboarding 为准。

```sh
cd flutter/jinbao365_app
flutter pub get
flutter run
```

首次运行选择本机身份，再连接自己的 COS。测试构建支持不保存密钥、不上传的占位连接，可先查看本地界面。开发测试请使用合成记录和独立测试桶。

DaysWith 沿用既有 package/bundle ID、Keychain service、档案路径和协议身份，保持兼容。覆盖升级需要原签名；请保留原手机与独立原件副本，按 onboarding 验证，不要通过卸载或清数据测试迁移。

## 费用、存储和使用边界

当前代码没有 DaysWith 会员订阅机制，可按 MIT 许可自行构建。用户自有 COS 的存储、请求、流量等费用由用户承担，具体以云服务商计费为准；账号、访问权限、密钥和备份维护也需要自行管理。

COS 是云服务商提供的对象存储。应用直接向 COS 发出签名请求，记录和媒体由用户配置的桶承接；DaysWith 当前没有提供托管存储服务，也没有完整的自托管服务端方案。

备份以应用前台运行和网络条件允许为前提，不保证锁屏、切后台或进程退出后持续传输。当前没有端到端加密；媒体也可能保留原文件名、拍摄时间、位置和 EXIF。配置自己的存储，不等于已经解决完整换机、数据长期保存和访问权限问题，使用前请了解 [数据流与权限边界](docs/ONBOARDING.md#5-数据流与权限边界) 及 [备份、恢复与升级](docs/ONBOARDING.md#6-备份恢复与升级)。
